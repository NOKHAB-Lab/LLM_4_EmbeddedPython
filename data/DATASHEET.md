# Datasheet — Hardware-Aware Embedded Python Code Dataset

Format follows *Datasheets for Datasets* (Gebru et al., 2021). Version 1.0.

## Motivation
- **Purpose.** Supervised fine-tuning and evaluation of LLMs for **hardware-aware embedded
  Python** on single-board computers (Raspberry Pi): GPIO, I2C, SPI, UART, PWM, camera/CV,
  sensors, networking/MQTT. General code LLMs produce code that is syntactically valid but
  physically non-functional; this dataset targets that gap.
- **Created by** the dataset authors for the paper *"LLMs for Hardware-Aware
  Embedded Python Code Generation: Benchmark-Driven Comparative Study"*

## Composition
- **Instances:** instruction→code pairs, `{id, prompt, completion, categories, metadata}`.
  Released file `dataset_clean.jsonl`: one JSON object per line, each with a unique opaque `id`
  (e.g. `llm4ep-b744ff9171ca`). The full corpus described in the paper is 17,000 pairs;
  community-sourced examples whose licenses are still being verified are withheld from this
  release and will be added in a future version once verified. Some rows share a completion
  with a reworded prompt (prompt-level augmentation).
- **Provenance:** three sources — synthetic (LLM-generated), manual (LLM output from hand-written
  prompts, **not** hand-written code), and community (scraped from public GitHub). Per-record
  `source_repo`, `source_url`, `license`, and `license_class` (community records) are in
  `metadata.provenance`; see the paper for the corpus composition.
- **Hardware domains/categories/sub-categories:** 6 broader categories; 18 functional/hardware
  multi-labels (GPIO, I2C, SPI, UART/serial, PWM/motor, camera/CV, sensors, networking, display,
  data-logging, config, DB, simulation, ML, etc.).
- **Labels/metadata per record:** `task` (nullable), `complexity`, `categories`, and
  `provenance` (license, redistributable, plus source_repo, source_url, license_class for
  community records). `complexity` takes exactly one of `basic`, `intermediate`, `advanced`.
  `task` is a free-text human-readable label and is `null` on community-sourced records
  whose description was lost by a defect in the ingest step; use `categories`, which is
  populated on every record, for filtering. See KNOWN_ISSUES.md.
- **Quality:** all records pass the validation-in-the-loop checks and **parse as valid Python 3**;
  see the paper for the full evaluation.
- **Sensitive data:** Author/maintainer emails appear inside third-party code as part of
  copyright/license notices (retained intentionally — required for MIT attribution). Real
  credentials were removed in the PII/secret scrub: a Dropbox token, a Google API key set
  (32 occurrences across 28 rows → `YOUR_API_KEY`), and a Gmail login/password pair
  (`jetsonstypv@gmail.com` / `STYPV@jetson`, 4 rows → placeholders); incidental emails and weak
  hardcoded passwords were also placeholdered.

## Collection process
- **Synthetic:** generated via the Google **Gemini API** from templated prompts, then
  syntax/pylint/structure-validated.
- **Manual:** generated by an LLM from hand-authored prompts.
- **Community:** scraped from public **GitHub** repositories (GitHub API, repos sorted by stars)
  and the **StackOverflow** BigQuery public dataset. The GitHub portion (162 repos) is what
  appears in the final corpus. Each scraped file's source URL is preserved
  (`raspberry_pi_code_dataset.json` → `provenance.source_url`).
- **Timeframe:** collected April 2025.

## Preprocessing / cleaning / labeling
- Deduplicated (exact prompt+completion), 4 corrupt JSON lines removed.
- Markdown fences stripped; whitespace normalized.
- **Licensing:** every community program traced to its repo; license resolved via GitHub API +
  `raw.githubusercontent` LICENSE/README/header inspection. **Copyleft (GPL/AGPL) removed.**
  Community code **without a verified license is withheld from this release**; those examples
  will be released in a future version once their licenses are verified or permission obtained.
- **PII/secret scrub:** removed a Dropbox token, a Google API key set, and a Gmail login/password
  pair, plus incidental emails and weak hardcoded passwords (→ placeholders);
  **author/license-attribution emails preserved** for MIT compliance.

## Uses
- **Intended:** fine-tuning/evaluation of code LLMs for embedded/Raspberry-Pi Python.
- **Not recommended:** safety-critical or production deployment without human review; the code is
  not security-audited.
